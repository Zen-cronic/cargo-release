## Demo thesis

Cargo Release turns scattered General Average evidence into a receipt-gated physical cargo release
for an unlikely enterprise hero: the cargo claims coordinator. The twist is that the model never
decides release. It prepares and routes work, while one human attestation and two independent,
issuer-bound keys are the only facts that can open the container. The long-tail adjustment remains
`OPEN` after physical release.

## Recording setup

1. Record the light-default browser at **1920×1080**, 100% zoom, 25 or 30 fps, H.264, with
   notifications hidden. Do not switch to the optional dark theme during the take.
   Use Recordly/OBS or another OS recorder for the clean take. Playwright is the rehearsal driver,
   not the final encoder.

   GCP proof beat.

   shell history, or billing data visible. The command should publish one synthetic casualty event,

   ```bash
   CARGO_RELEASE_RECORDING_EVENT_APPROVED=I_APPROVE_ONE_MARKED_SYNTHETIC_RECORDING_EVENT \
     ./scripts/publish_recording_event.sh
   ```

   Commit `2ea8098` guards this exact one-event trigger. Its no-approval preflight exits `3` before
   calling Google Cloud and its output contains only the marked safety line, message ID, mission ID,
   public mission URL, and expected human gate.
5. Prepare browser tabs in this order: live mission room, sanitized trigger terminal, optional Agent
   Runtime Console page, final released mission room. Close unrelated tabs.
6. Use only fictional case data. Never expose Secret Manager payloads, ID tokens, personal account
   information, or real-party identifiers.
